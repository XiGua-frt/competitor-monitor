# TK 跨境选品关键数据采集清单（爬虫开发用）

> 目标：为选品分析漏斗（Pool→初筛→深筛→测试→放大）提供自动化数据底座。
> 适用环境：美区 TikTok Shop；复用本地爬虫栈（真实浏览器 session cookie + curl_cffi chrome131 + 127.0.0.1:7892 出口）。
> 优先级说明：P0 = MVP 必采；P1 = 二期；P2 = 可后置。

---

## 0. 数据源总览与取舍

| 数据源 | 能拿到的核心数据 | 成本 | 可信度 | 局限 | 优先级 |
|--------|----------------|------|--------|------|--------|
| TikTok Shop 前台 Web（类目榜/商品页/店铺页） | 商品、价格、销量、店铺 | 免费 | 高（真实前台数据） | 榜单只露头部、销量常为区间值 | P0 |
| TikTok 视频流 / 标签页 / 达人主页 | 视频指标、话题、达人粉丝 | 免费 | 高 | 需登录态，风控最严 | P0 |
| Kalodata / EchoTik / FastMoss | GMV 估算、达人带货明细、类目趋势 | 付费（约 $50-200/月） | 中（第三方估算，但胜在聚合） | 采样估算、有延迟 1-3 天 | P1 |
| TikTok 官方开放 API（Shop/Creator） | 自家店铺与授权达人数据 | 免费 | 最高 | 需商家/开发者资质，拿不到竞品数据 | P2 |
| Google Trends | 需求趋势验证 | 免费 | 高 | 只有相对指数，无绝对量 | P1 |
| 1688 / 供应商页 | 采购价、MOQ、交期 | 免费 | 中 | 需人工二次确认快返能力 | P1 |
| Amazon 前台（BSR/评论/价格） | 需求交叉验证 | 免费 | 高 | 与 TK 人群不完全重叠 | P1 |

**取舍结论**：P0 自建爬虫抓 TK 前台（需求+内容+竞争），P1 辅以第三方工具补 GMV 估算、1688 补供应链，官方 API 仅作自有店铺数据回流，不作选品来源。

## 1. 商品维度（P0，选品主表）

| 字段 | 说明 | 采集来源 | 用途 |
|------|------|---------|------|
| product_id | 商品唯一 ID（可从 URL 提取） | 商品页 URL | 主键、去重、追踪 |
| title | 商品标题 | 商品页 | 品类归类、关键词提取 |
| category_l1/l2/l3 | 三级类目路径 | 类目榜/商品页面包屑 | 类目筛选、市场分层 |
| price_current | 当前售价（USD） | 商品页 | 价格带筛选（$15-40 甜点区） |
| price_original | 原价/划线价 | 商品页 | 折扣力度、利润测算 |
| sales_30d | 近 30 天销量（区间值取中位数） | 商品页销量标签 | 需求规模 |
| gmv_30d_est | 近 30 天 GMV 估算 = price × sales 中位数 | 自算 | 市场规模排序 |
| gmv_growth_7d/30d | 销量环比增速（需多次快照对比） | 快照差分 | 识别飙升品（漏斗 Pool 入口） |
| listed_date | 上架时间（越新越有先发机会） | 商品页 | 排除老链接垄断品 |
| shop_id / shop_name | 所属店铺 | 商品页 | 竞品店铺追踪 |
| shop_type | 跨境店 / 本土店 | 店铺页 | 竞争对手结构分析 |
| creator_count | 关联带货达人数 | 商品页"达人带货"模块 | 分发广度、饱和度 |
| video_count_7d | 近 7 天关联视频数 | 商品页视频列表 | 内容热度、内容效率计算 |
| review_count / rating | 评论数与评分 | 商品页 | 需求真实性交叉验证 |
| is_promotion | 是否在活动/闪购位 | 榜单标签 | 剔除活动干扰 |

> 采集要点：`gmv_growth` 无法单次抓到，必须**对同一商品 ID 做周期快照（建议每 2-3 天）**，差分算增速——这是整个选品系统最值钱的字段。

## 8. 派生指标（不采集，入库后计算）

| 指标 | 计算公式 | 用途 |
|------|---------|------|
| 内容效率 | gmv_30d_est ÷ video_count_7d | 单条视频产出，判断素材质量 vs 单纯砸量 |
| 达人渗透率 | creator_count ÷ sales_30d | 谁在推：达人驱动 vs 店铺自播驱动 |
| 饱和度指数 | creator_count × video_count_7d / gmv_30d_est | 越高越卷，漏斗初筛排除项 |
| 飙升系数 | gmv_growth_30d ÷ 类目平均增速 | Pool 榜单核心排序字段 |
| 定制类退货拨备 | price × 预估退货率(服装 15-25%) | POD 品净利修正（退货即全损） |

## 9. 采集实施顺序建议

1. **P0（MVP，先跑通闭环）**：类目榜快照 → 商品详情（1 章 15 字段）→ 商品关联视频流。核心是"商品快照 + 差分算增速"。
2. **P1（二期）**：达人简版、标签趋势、竞品店铺监控、1688/Google Trends/Amazon 交叉验证。
3. **P2**：官方 API 回流自有店铺实际成交数据，校准 GMV 估算系数。

**风控提醒**：TK 前台风控最严的是视频流与达人主页，商品页/类目榜最松。建议按"商品页为主、视频页采样（每商品抽 top 10 视频而非全量）"设计配额，请求间隔 ≥5-8s 随机化，复用现有 chrome131 指纹栈。

**数据诚实性约束**：前台销量为区间值、第三方 GMV 为估算，所有分析输出必须标注数据来源与置信级别，估算字段禁止当精确值用于最终决策。
