## TikTok 公开数据抓取项目调研
- GitHub 搜索 + 交叉验证，产出推荐清单（第一梯队：Evil0ctal/Douyin_TikTok_Download_API 20.3k★ 活跃、davidteather/TikTok-Api 6.6k★ 活跃；高星已死：drawrowfly/tiktok-scraper 2023-05 停更勿用）。
- 深入分析 kiryano/Scout（658★，达人线索工具）：TikTok 采集原理 = GET tiktok.com/@{user} 解析 `__UNIVERSAL_DATA_FOR_REHYDRATION__` blob（webapp.user-detail），仅 profile 级字段（username/nickname/bio/bio 提取 email/verified/follower/following/heart/video_count），无视频列表/评论/搜索。
- 实测：当前网络直连 tiktok.com 被 Slardar WAF 拦截（返回 1462 字节挑战页，无 rehydration blob）→ Scout 必须配代理（SCOUT_PROXY / 住宅代理）。
- 结论：Scout 适合达人名单→邮箱线索→CSV→飞书 Bitable 的轻量触达链路；深度数据（视频互动/评论）仍需 TikHub 或 davidteather/TikTok-Api。

- Evil0ctal/Douyin_TikTok_Download_API（93 个 REST 操作）含抖音+TikTok 搜索端点，自托管 API 服务形态，细节以实例 /docs swagger 为准。
- cv-cat/TiktokApis（145★，2026-09-22 更新）含搜索但要求完整登录浏览器会话证据（cookie+msToken+device_id+browser_metrics），偏逆向研究。
- CrotDalam v0.3.0 已砍掉 search 功能（引擎未随发布），排除。

## 数据源决策变更：弃用 TikHub，改自建爬虫
- 用户拍板不用 TikHub（第三方转售 API 已在计划 §4.1 表中标记为"已否决"）。
- 自建爬虫实机探测结论（已写入计划 §4.4）：
  - 匿名 SSR 抓搜索 = 结构性死路（搜索页 383KB HTML 中 0 条视频，结果全靠客户端签名 XHR /api/search/general/full/）。
  - 匿名抓 profile = Slardar WAF JS 挑战壳拦截，Scout 现有 app/scrapers/tiktok.py 已失效。
  - 唯一可行路径 = 签名 API + 用户自有浏览器会话（Cookie+msToken+device_id+browser_metrics 同会话、单会话不建池）。
- TiktokApis 仓库无 LICENSE（默认保留所有权利）→ 生产签名/解析代码必须自研，仅作研究参考（signing/pure.py 证明纯 Python 签名可行）。
- 环境注意：开发机沙箱出口 IP 已被 TikTok 限流（oembed 429、间歇 TLS reset）；期间沙箱代理(127.0.0.1:64724)曾抖动导致误判"被 TikTok 拉黑"，诊断时先跑 google/httpbin 基线再下结论。
- 下一步：用户从自己浏览器提供一次会话材料 → 首验 profile rehydration + search_general ItemModule → 自研签名实现进 Scout/discovery。
