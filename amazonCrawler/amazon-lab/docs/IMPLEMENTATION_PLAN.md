# Amazon 六步采集模块实施计划

目标：把已完成的采集条件核对和相关性筛选接入可恢复、可限流、可追踪的本地单进程模块。用户已授权完成全部六步；复用本地 AmzPy，不使用付费采集 API。

## 边界与接口

- 保留原 probe、页面、历史 JSON。正式入口为 collect.py，正式状态在 data/collector.sqlite3；演示和测试使用 test 下独立状态。
- SQLite 是任务、缓存、运行控制和快照的唯一状态源；schema 版本 1，无 Redis 或新增服务。
- Repository：enqueue、claim、complete_snapshot、fail、latest、reserve_request、pause/cooldown、scheduler_due、运行租约。
- RequestGuard：请求前原子预留预算；固定域名，禁用跳转；短间隔等待；429 冷却、403/验证码/地区失效暂停；超时/5xx 有限延迟重试。
- AmzPyAdapter：仅一次底层请求，复用现有搜索和详情解析，不使用上游重试或隐式请求；会话不输出。
- Pipeline：搜索保存发现→入队未缓存候选→详情核对/归一化→原子保存快照并完成任务；记录失败及运行统计。
- Scheduler：持久搜索周期和商品到期刷新；进程租约避免重叠；支持单次 tick、前台持续运行、暂停/恢复。
- Report：最新观察、最近有效价格及原时间、全部历史快照、字段空值率、预算/异常/任务状态；BSR 按类目，近期购买量仅保留展示下界和窗口，不算销量。

## 执行顺序

1. 数据存储：写并运行失败测试，再实现 schema、跨次去重、任务租约、快照幂等、缓存到期；测试重启与崩溃恢复。
2. 请求控制：写并运行失败测试，再实现滚动小时/24 小时预算、间隔、429 冷却、异常暂停、网络/5xx 重试；测试预算预留、重启和时钟。
3. 编排与指标：写并运行失败测试，再接入两个现有步骤和受控 AmzPy adapter；只对满足条件的快照比较，卖家变化或缺值注明不可计算。
4. 调度与交付：写并运行失败测试，再实现 CLI、持久调度、独立模拟演示、历史导入、JSON/Markdown 报告、Windows 入口与文档。
5. 验收：运行全部旧/新测试，离线导入原样本两次验证幂等，运行断点/冷却/异常模拟；检查历史证据未改变、日志不含会话值。

## 验收重点

- 同一采集条件重复发现不重复建档；缓存到期才安排详情；不同邮编/变体分开保存，预算仍共用。
- 请求次数在联网前保存，失败/重试也计数；进程重启不能重置配额或绕过冷却；跳转不产生未记账请求。
- 快照按真实观察保存，不用日期覆盖；任务完成与快照入库原子提交，失败不覆盖最近成功数据。
- 未固定变体、币种/卖家变化、字段缺失、BSR 类目不一致均不强算价格/排名趋势；评分数量差不是销量。
- 调度不补跑无限积压，不在暂停时发请求；同一任务可恢复，但不可无限重试。
- 完成代码与模拟验证不等于真实长期稳定性。前台调度入口交付，不自动注册后台长期采集。

## 实施结果（2026-10-10）

- 六步已接入 collect.py，Windows 启动入口为 start-collector.ps1；说明见 README_COLLECTOR.md。
- 81 项离线自动测试通过，覆盖原条件/相关性、重启去重、任务恢复、配额、冷却、暂停、快照比较、调度、CLI 和幂等导入。
- 独立只读评审发现并修复租约接管后旧 worker 继续工作、未固定变体仍计算趋势，以及解析期间租约丢失错误暂停新 worker 的问题；复核通过。
- 历史数据已导入正式库：48 条发现记录、40 个候选商品档案、3 条保留原时间的商品快照；未建立真实运行任务，新增请求为 0。
- 原 JSON/HTML 证据哈希在幂等导入测试前后相同。
- 独立回放验证：首轮 4 次模拟请求产生 3 条快照，缓存轮 0 请求；到期新增 3 条，历史共 6 条；429 冷却重启并 resume 后仍有效。
- 长期真实稳定性、完整变体绑定和真实页面适配仍待验证；前台调度已交付，未启动后台采集。
