# Amazon 美国站六步采集模块

已实现六步完整链路：**固定条件核对 → 搜索相关性筛选 → 跨次缓存与任务去重 → 持久请求控制 → 增量快照与比较 → 定时调度与报告**。使用本地 AmzPy；没有第三方付费采集 API。单机 SQLite 存储，无额外数据库服务。

## 六步如何工作

| 步骤 | 行为 | 留下的结果 |
|---|---|---|
| 1 条件核对 | 固定 Amazon.com、10001、USD、英语；从页面独立核对地区、实际 ASIN、尺码、颜色、版型 | collection_conditions，期望值、页面证据、异常和比较资格 |
| 2 相关性 | 依据商品文字判断人穿服装、定制、宠物肖像；剔除宠物穿衣等；证据不足待确认 | discoveries 中保留原位置、相关性理由、重复及入队决策 |
| 3 缓存去重 | 同一 ASIN/条件仅一个活动任务；24 小时有效缓存；到期刷新；重启恢复任务 | products、tasks、快照及持久租约 |
| 4 请求控制 | 请求前原子记账；限流、冷却、暂停、有限重试，所有运行和关键词共用账本 | requests、控制状态和失败原因 |
| 5 历史比较 | 每次成功保存独立快照；失败不覆盖；比较前核对地区和变体；价格另核对卖家与币种 | 最新观察、历史、最近有效报价及原观察时间、可计算的差值 |
| 6 调度交付 | 按持久到期时间搜索和刷新；空闲时不初始化客户端；前台循环支持退出后恢复 | 每轮运行记录、Markdown/JSON 报告 |

统一记录包含标题、描述、链接、图片、品牌、卖家、上架日期、价格、币种、评分、评分数量、BSR、近期购买量原文，以及尺码、颜色、版型和变体证据。缺失保留 null。

## 使用

在 PowerShell 进入 `解压目录\amazon-lab`，执行以下命令。默认入口只看状态，不联网。

```powershell
.\start-collector.ps1 status
.\start-collector.ps1 dry-run
.\start-collector.ps1 import-saved
.\start-collector.ps1 report
.\start-collector.ps1 demo
```

`import-saved` 将此前 48 条搜索记录和 3 件商品详情导入状态库，重复导入不会增加重复快照，保留 10 月 8 日原采集时间。历史价格不是今天的新报价。`demo` 在 test 下独立演示搜索、缓存、刷新、429 冷却和重启，不访问 Amazon。

以下是**真实联网入口**，使用本地已保存的美国配送偏好会话：

```powershell
.\start-collector.ps1 once
.\start-collector.ps1 schedule
```

`once` 执行一轮并退出；`schedule` 前台持续调度，每 10 秒检查到期任务，Ctrl+C 停止。另一终端可以执行 `pause`；执行 `resume` 清除暂停，但不能清除冷却、请求间隔或配额。调度进程未注册为系统后台服务，电脑关机时不执行，重新启动命令后读取持久状态。

只刷新已有商品、或只执行一次调度检查：

```powershell
.\.venv\Scripts\python.exe -I collect.py once --refresh-only
.\.venv\Scripts\python.exe -I collect.py schedule --once
```

旧 `probe.py` 的默认联网执行已转入正式受控入口；旧 `--same-products`、`--check-redirect` 独立联网诊断已停用。原实验函数保留用于离线回归。

## 配置与停止条件

`runtime_config.json` 默认每轮最多 4 次请求/3 件详情，每滚动小时 8 次、滚动 24 小时 12 次，至少间隔 15 秒；搜索和详情刷新周期均为 24 小时。失败、重试和中断前预留都计入预算。配额是本模块的保守运行参数，不代表平台保证允许的请求频率。

429 至少冷却一小时并遵守更长 Retry-After；403、验证码、登录页面、跳转、地区失效或解析结构无法确认时暂停。网络/5xx 最多两次尝试，延迟重试；连续三次错误暂停。暂停后先查看报告原因、恢复正常会话/页面条件，再恢复。不会轮换账号、代理或自动绕过验证码。

`collection_conditions.json` 的 `tracked_variants` 可逐商品登记已人工核对的子 ASIN 和页面选中值，例如：

```json
{"B000000001":{"asin":"B000000001","size":"Small","color":"Black","fit_type":"Men"}}
```

示例 ASIN 是占位符，不可直接使用。当前三件历史商品未全部完成变体身份确认，因此只记录已看到的值，比较资格仍为未确认。模块不会自动点击所有尺码/颜色，也不会把未知值补成默认值。确认真实子 ASIN 和完整变体后，直接采集对应页面；若选择值不符，保留证据并阻止趋势比较。改变邮编或变体会生成独立条件档案，但不会重置请求账本。

## 查看结果

- `data/collector.sqlite3`：持久状态、任务、快照、请求账本。
- `data/reports/REPORT.md`：可读报告。
- 同目录 `latest.json`、`history.json`、`tasks.json`、`report.json`：完整字段、历史、任务与变化。
- `data/runs/`：逐轮记录；`data/evidence/`：请求页面和证据摘要。
- `F:\shop\crawler-lab\test\amazon\amzpy\six-step-demo\LATEST.json`：最近演示目录。

评分数量不是文字评论数量，其变化不是订单数量；BSR 是类目排名，不能转成精确销量。近期购买提示只保存原文、下界及页面窗口，不将两次提示相减为新增订单。页面价格不是最终定制订单金额。缺价快照保留空值，最近有效报价单独显示并保留原时间。

## 验证边界

已完成离线自动测试、原 HTML 的 AmzPy 解析、历史幂等导入，以及独立模拟端到端运行。本轮升级未发起新的 Amazon 请求，未启动持续联网调度；真实页面变化、会话长期有效性和连续运行稳定性仍需小规模实际运行验证。

本实现借鉴所提供文档的分层、持久化、控制和历史设计，结合 Amazon 业务落地。没有照搬文档中的 TikTok 身份池、签名、代理或 GMV 模型，也没有引入其多节点基础设施。
